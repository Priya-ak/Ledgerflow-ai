# API documentation

Interactive docs are generated by FastAPI at **`/api/docs`** (Swagger UI) and **`/api/redoc`** when the backend is running. The full machine-readable schema is in [`openapi.json`](openapi.json).

## Conventions

- **Base path:** `/api/v1`. The Next.js frontend proxies `/api/v1/*` to the backend, so browsers only talk to one origin.
- **Authentication:** `POST /auth/login` sets an httpOnly `lf_session` cookie (SameSite=Lax, Secure outside development) and also returns `access_token` for non-browser clients, which send `Authorization: Bearer <token>`. Logout, password reset, role change and deactivation increment the user's `token_version`, which revokes every previously issued token.
- **Authorization:** every protected route declares a permission (column *Permission* below) that is checked on the server. Tenant scope always comes from the authenticated user, never from the request. Records from another company return **404** (not 403) so their existence is not revealed.
- **Money:** all amounts are JSON **strings** with exact decimals (e.g. `"19293.00"`). Never parse them as floats for arithmetic.
- **Pagination:** list endpoints accept `page` (≥1) and `page_size` (≤100) and return `{items, total, page, page_size}`.
- **Errors:** every error uses one envelope, and the `X-Request-ID` response header matches `request_id`:

```json
{"error": {"code": "business_rule_violation", "message": "Invoice has unresolved critical validation errors and cannot be approved.", "details": null, "request_id": "0b6f..."}}
```

| Status | Code | Meaning |
|---|---|---|
| 401 | `unauthorized` | Missing, expired or revoked session |
| 403 | `forbidden` | Authenticated but lacking the permission, or a segregation-of-duties rule |
| 404 | `not_found` | Not found in *your* company |
| 409 | `conflict` | Unique value already used (email, supplier code, PO number) |
| 413 | `file_too_large` | Upload over `MAX_UPLOAD_MB` |
| 415 | `unsupported_file` | Content is not a valid PDF/JPG/PNG or does not match its extension |
| 422 | `validation_error` / `business_rule_violation` | Schema validation failed, or a workflow rule blocked the action |
| 429 | `rate_limited` | Too many login/registration/reset attempts |
| 500 | `internal_error` | Unexpected error (details only in server logs) |

## Example: process an invoice with curl

```bash
# 1. Sign in (token returned for API clients)
TOKEN=$(curl -s -X POST http://localhost:8000/api/v1/auth/login -H 'Content-Type: application/json' \
  -d '{"email":"accountant@ledgerflow-demo.example","password":"LedgerFlow2026"}' | python -c "import sys,json;print(json.load(sys.stdin)['access_token'])")

# 2. Upload a document (type is verified from content)
DOC=$(curl -s -H "Authorization: Bearer $TOKEN" -F file=@sample-data/synthetic-invoices/06_po_mismatch.pdf \
  http://localhost:8000/api/v1/documents/upload | python -c "import sys,json;print(json.load(sys.stdin)['id'])")

# 3. OCR + extraction + duplicate/PO/validation checks -> invoice for review
curl -s -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d "{\"document_id\":\"$DOC\"}" http://localhost:8000/api/v1/invoices/extract
```
